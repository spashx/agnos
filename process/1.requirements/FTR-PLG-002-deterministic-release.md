# FTR-PLG-002: A Deterministic Release and a Report a Person Reads

## Overview
A rehearsal of `agnos-meta-release` gives the same result whoever runs it, an agent or a person, on whatever tool: the output holds exactly
what is declared, the console says everything to act on, and a page beside the JSON report lets the owner read it.

Source: the owner's review of 2026-11-03. The rehearsal of `1361a8b` left three `__pycache__` files in the marketplace, passed with Claude Code
absent, and gave its exit code and its lines to read only to an agent that opened the JSON.

Out of scope: publishing, which stays the owner's decision (DEC-PLG-007); the checks of FTR-MTA-002, unchanged.

## Stakeholders
- **Owner**: the repository owner (maintainer of AGNOS).
- **Consumers**: the owner reading the report; the agents running `agnos-meta-release` and `agnos-meta-plugin-proof`.

---

## Functional Requirements

### RQ-PLG-012: The output holds what is declared, nothing more
- **Category**: Functional
- **EARS Type**: Unwanted-behavior
- **Statement**: IF the output folder holds a file that is neither delivered nor generated by the build, THEN `agnos-meta-release` SHALL fail and name the file; its checks SHALL write no cache, such as Python's `__pycache__`, into the output.
- **Rationale**: the rehearsal of `1361a8b` delivered three `.pyc` files of the maintainer's Python version, and no check saw them.
- **Priority**: Must
- **Acceptance Criteria**: Given a rehearsal, Then the files on disk are exactly the delivered and generated ones, And no `__pycache__` exists; Given a file added to the output before the inventory, Then the exit is 1 and the file is named.
- **Dependencies**: RQ-MTA-006, RQ-PLG-001

### RQ-PLG-014: The console says everything to act on
- **Category**: Functional
- **EARS Type**: Ubiquitous
- **Statement**: `agnos-meta-release` SHALL print the report's `problems`, `toRead`, `mentions` and `idsOutsideComments`, each with its file and line, and SHALL end with one line giving `exit=<code>`, the files on disk, the IDs removed, the lines to read and the duration. Amends RQ-MTA-012 on the summary line.
- **Rationale**: the summary line gave a count of lines to read and no exit code, so what the owner saw depended on the agent opening the JSON.
- **Priority**: Must
- **Acceptance Criteria**: Given a rehearsal with lines to read, Then each is printed with its file and line; Given any rehearsal, Then the last line starts with `agnos-meta-release: exit=` followed by the process's exit code.
- **Dependencies**: RQ-MTA-012

### RQ-PLG-015: The manifests checked by the release itself, whatever the tool
- **Category**: Functional
- **EARS Type**: Unwanted-behavior
- **Statement**: IF a manifest or catalogue of the output lacks a required field, names a path that does not exist, or differs from the others in name, version or description, THEN `agnos-meta-release` SHALL fail and name it; the release SHALL call no AI tool, and the validation by each tool SHALL stay with `agnos-meta-plugin-proof`.
- **Rationale**: the rehearsal of `1361a8b` passed with `claude` absent, and a maintainer using only GitHub Copilot could never run Claude Code's validation; the proof already runs it and installs for real.
- **Priority**: Must
- **Acceptance Criteria**: Given the output, Then the report's `checks` hold `manifests: true`; Given a manifest missing its version, or a catalogue naming a missing plugin folder, Then the exit is 1 and the file is named; Given no `claude` on the machine, Then the verdict is the same.
- **Dependencies**: RQ-PLG-002, RQ-PLG-010

### RQ-PLG-016: A page for the report
- **Category**: Functional
- **EARS Type**: Ubiquitous
- **Statement**: `agnos-meta-release` SHALL write `<folder>.report.html` beside `<folder>.report.json`: one self-contained page, read offline with no library, showing the commit, the outcome, each check, the problems, the lines to read, the mentions, the IDs outside comments, the files delivered and left out, and the IDs removed per file.
- **Rationale**: the owner judges the lines to read before publishing, and a JSON file is written for tools.
- **Priority**: Must
- **Acceptance Criteria**: Given a rehearsal, Then the page exists And holds every value of the JSON report it lists; Given a text of the report holding `<script>`, Then the page shows it as text; Given no network, Then the page displays fully.
- **Dependencies**: RQ-MTA-012, RQ-PLG-017

## Non-Functional Requirements

### RQ-PLG-013: Same commit, same output
- **Category**: Non-Functional
- **NFR Type**: Reliability
- **EARS Type**: Ubiquitous
- **Statement**: Two rehearsals of the same commit SHALL write byte-identical output folders and reports, the duration aside.
- **Metric**: 0 differing files between two runs.
- **Measurement Method**: a test rehearsing twice and comparing the trees and the reports.
- **Priority**: Must
- **Acceptance Criteria**: Given two rehearsals of HEAD into two folders, Then every file is equal byte for byte, And the JSON reports are equal.
- **Dependencies**: RQ-MTA-007, RQ-PLG-012

### RQ-PLG-017: The page follows the perf center's design system
- **Category**: Non-Functional
- **NFR Type**: Usability
- **EARS Type**: Ubiquitous
- **Statement**: The report page SHALL take every visual value from the design tokens of `agnos-perf-center` (RQ-TRC-018, ADR-TRC-002), in the commit rehearsed, and SHALL hold no raw visual literal; it SHALL follow the reader's light or dark theme.
- **Metric**: 0 colour, size or spacing literal in the page's stylesheet outside the custom properties compiled from the tokens.
- **Measurement Method**: a test searching the stylesheet for literals; the owner's reading of the page.
- **Priority**: Must
- **Acceptance Criteria**: Given the page's stylesheet, Then every visual value is a `var(--…)` of the compiled tokens; Given a dark theme, Then the page uses the dark values.
- **Dependencies**: RQ-TRC-018, ADR-TRC-002
