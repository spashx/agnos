# AGENTS.md — AGNOS Process Entry Point for AI Coding Agents

<!-- RQ-AGT-001 / TASK-AGT-001 -->

This repository is developed under the **AGNOS** software engineering process. Any AI coding agent
working here (Codex, Cursor, Gemini, Windsurf, Aider, Copilot, Claude Code or other) SHALL follow it
in full, for every change, however small.

## 1. Load the process first

Before any other action, read **in full**:

**[`.github/instructions/agnos-sw-eng.instructions.md`](.github/instructions/agnos-sw-eng.instructions.md)**

Claude Code already holds that file, through the import of `CLAUDE.md`; every other agent reads it. <!-- RQ-AGT-002 / TASK-AGT-003 -->

That file is the single normative source of the process. This file only tells you where things are
and how to map the process to your tool; where they disagree, the instructions file wins. Do not
rely on a summary, including the README.

Run its **START SESSION ACTION** when the user asks to start a session, and its **END SESSION ACTION**
when the user closes it. <!-- RQ-INI-010 -->

`.github/instructions/agnos-sw-eng.instructions.md` is the improvement target: in this repository, a
recursive self-improvement session improves the process in that file itself. <!-- RQ-RSI-002 / DEC-RSI-002 -->

## 2. Non-negotiable rules (reminder, not a substitute)

- Work only on the `feature/<TRI>` session branch — never on `main` / the default branch.
- Every artifact and every code change cites its requirement ID, in comments.
- Every task is tiered (S / M / L), presented to the user, and started only after explicit approval.
- `agnos-process/process.idx.md` is generated by the `agnos-index` skill — never edit it by hand.
- Shell commands follow `platform` in `agnos-process/_sessionstate/session.yaml`.
- One targeted fix per failure, then stop and report (Error Recovery Protocol).

## 3. Skills

The process delegates its deterministic operations to skills. The canonical procedure of each is a
`SKILL.md` under `.github/skills/<name>/`. If your tool discovers skills, invoke them by name; if it
does not, **read the `SKILL.md` and follow its procedure literally** wherever the process names the
skill.

| Skill | Procedure | Used for |
|---|---|---|
| `agnos-init` | [`.github/skills/agnos-init/SKILL.md`](.github/skills/agnos-init/SKILL.md) | Add AGNOS to a project, or update it there: completes its entry-point files and creates `agnos-process/` <!-- RQ-INI-009 --> |
| `agnos-session` | [`.github/skills/agnos-session/SKILL.md`](.github/skills/agnos-session/SKILL.md) | `init` writes the session state at session start, `show` reloads it, `close` appends the friction-metrics row at session end <!-- RQ-INI-018 --> |
| `agnos-index` | [`.github/skills/agnos-index/SKILL.md`](.github/skills/agnos-index/SKILL.md) | Regenerate the artifact index — at session start and before every commit |
| `agnos-git-workflow` | [`.github/skills/agnos-git-workflow/SKILL.md`](.github/skills/agnos-git-workflow/SKILL.md) | `start-session <TRI>` (branch) and `commit-task <TASK> [<ADR>] <description>` (commit) |
| `agnos-design-system` | [`.github/skills/agnos-design-system/SKILL.md`](.github/skills/agnos-design-system/SKILL.md) | Create the design system of a UI project, before its first UI requirement |
| `agnos-perf-center` | [`.github/skills/agnos-perf-center/SKILL.md`](.github/skills/agnos-perf-center/SKILL.md) | Monitor the process's execution on a project (traceability matrix, quality, history, delivery) — at session end or before a release |
| `agnos-self-improvement` | [`.github/skills/agnos-self-improvement/SKILL.md`](.github/skills/agnos-self-improvement/SKILL.md) | Run a recursive self-improvement effort on the declared improvement target, within its line budget — END SESSION step 3 <!-- RQ-RSI-001 --> |

Each skill's scripts exist for Windows PowerShell 5.1 and bash, or are Python; the `SKILL.md` says
which to run for the session's `platform`. Never reimplement a skill's work by hand.

## 4. Tool mapping

| The process says | Do this |
|---|---|
| `askQuestion` / `AskUserQuestion` (the user-question tool) | Use your tool's structured question feature; if it has none, ask one explicit question in chat and **wait** for the answer before continuing |
| "invoke the `<name>` skill" | Invoke it natively, or read and follow `.github/skills/<name>/SKILL.md` |
| "present the task and wait for approval" | Stop your turn; do not continue until the user approves |
| "commit" | Only through `agnos-git-workflow commit-task` — never a raw `git commit` |

Tool-specific entry points also exist for GitHub Copilot (`.github/instructions/`,
`.github/skills/`) and Claude Code (`CLAUDE.md`, `.claude/skills/`). This file serves every agent: Claude Code
reads it through the import of `CLAUDE.md`, and GitHub Copilot in VS Code reads a workspace-root `AGENTS.md` by
default. <!-- RQ-AGT-002 / TASK-AGT-003 -->
