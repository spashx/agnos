# FTR-WEB-001: The AGNOS Presentation Website, Built by agnos-meta-website

## Overview
The maintainer calls `agnos-meta-website` to build the AGNOS presentation website, for technical CIOs who know the challenges AI brings
to the software development life cycle. The site is a guided tour of the Performance Center generated on the demo project (Roombook):
each view, shown as a screenshot that opens the live demo, introduces the AGNOS concepts behind it. The text, in English and French, and
the images live in the skill's `assets/` folder, so the owner changes them without touching the page. The demo Performance Center page is
either given to the skill or regenerated by it, and is published with the site.

Out of scope: capturing the screenshots automatically (the owner replaces the placeholder images), opening the demo on a given view (a
separate Performance Center feature, RQ-TRC-121, which the site's links use since 2026-11-12), the demo's AI agent identities (a separate
`agnos-meta-demo` feature), publishing
(the build writes a folder; committing and pushing it stay with the owner).

## Stakeholders
- **Owner**: the repository owner (maintainer of AGNOS).
- **Consumers**: the CIOs and IT leaders reading the site; the maintainer editing its content; GitHub Pages serving it at
  `https://spashx.github.io/agnos.site/`.

## Functional Requirements

### RQ-WEB-001: A maintainer skill that builds the site in a folder
- **Category**: Functional
- **EARS Type**: Event-driven
- **Statement**: WHEN the maintainer calls `agnos-meta-website build --demo <demo repository> --out <folder>`, the skill SHALL write into
  `<folder>` the static site: `index.html`, the images under `screens/` and the demo Performance Center page under `demo/`, then print
  one summary line (fields per language, images) and exit 0; IF a check fails, THEN it SHALL write nothing, name each
  failure on the error stream and exit 1.
- **Rationale**: the site is regenerated from AGNOS's evolutions, never copied by hand.
- **Priority**: Must
- **Acceptance Criteria**: Given valid assets and the demo, When `build` runs, Then the folder holds `index.html`, `screens/` and `demo/`,
  And one summary line is printed, And the exit code is 0; Given a content error, When `build` runs, Then the folder is unchanged, And the
  error names the file and the field, And the exit code is 1.
- **Dependencies**: ADR-WEB-001

### RQ-WEB-002: The demo page, given or regenerated
- **Category**: Functional
- **EARS Type**: Event-driven
- **Statement**: WHEN `--demo-page <PERF-CENTER.html>` is given, the skill SHALL copy that page and its data files beside it into
  `demo/`; otherwise it SHALL generate the page with this working tree's `agnos-perf-center` on the demo repository, with `--history`, and
  `--call-graph` when its packages are installed.
- **Rationale**: the owner may already hold a demo page, or want the one the current AGNOS produces.
- **Priority**: Must
- **Acceptance Criteria**: Given `--demo-page`, When `build` runs, Then `demo/` holds that page and its data files, byte for byte; Given no
  `--demo-page`, When `build` runs, Then `demo/PERF-CENTER.html` is the output of `agnos-perf-center` on the demo, with its history.
- **Dependencies**: RQ-WEB-001, RQ-TRC-016

### RQ-WEB-003: The text and the images in the assets
- **Category**: Functional
- **EARS Type**: Ubiquitous
- **Statement**: The site's text SHALL come only from `assets/content/en.md` and `assets/content/fr.md`, one `##` section per page element
  and one `###` field per text, and its images only from `assets/screens/`; a field SHALL be one paragraph, one list, or one image written
  as a linked image `[![alternative text](screens/<file>.png)](<address>)`, with inline emphasis, strong, code and links allowed, a line
  ending in `\` forcing a line break and comments ignored; the page template SHALL hold no text.
- **Rationale**: the owner edits the words and replaces the images without touching the page (owner request of 2026-11-08).
- **Priority**: Must
- **Acceptance Criteria**: Given a word changed in `fr.md`, When `build` runs, Then the French page shows it and nothing else changes;
  Given an image replaced in `assets/screens/`, When `build` runs, Then the site shows the new image; Given the template, When its
  elements are read, Then each text element is empty and names its field.
- **Dependencies**: RQ-WEB-001

### RQ-WEB-004: The content checked before anything is written
- **Category**: Functional
- **EARS Type**: Unwanted-behavior
- **Statement**: IF a field is in one language only, a field is defined twice, a field holds a variable `{{<name>}}`, text stands
  outside a field, a field mixes a paragraph and a list or holds more than one paragraph, a field is unknown to the template, a
  template element has no field, or an image file is missing, THEN the skill SHALL report it with the file and the field, and exit 1.
  <!-- variable check moved from RQ-WEB-005 by TASK-WEB-017 (owner, 2026-11-13) -->
- **Rationale**: an edit by hand must not publish a half-translated or broken page.
- **Priority**: Must
- **Acceptance Criteria**: Given each of these faults in turn, When `build` runs, Then the error names it, its file and its field, And the
  exit code is 1.
- **Dependencies**: RQ-WEB-003

### RQ-WEB-005: Figures measured on the demo
- **Status**: Deprecated (owner, 2026-11-13, TASK-WEB-017): the index card states no measure; a variable left in a field is
  reported under RQ-WEB-004.
- **Category**: Functional
- **EARS Type**: Event-driven
- **Statement**: WHEN a field holds `{{index.documents}}`, `{{index.size}}`, `{{index.ratio}}` or `{{index.speed}}`, the skill SHALL
  replace it with the size of the demo's process documents, the size of its `process.idx.md`, their ratio written `1/<n>`, and the
  seconds `agnos-index` takes per 100 artifacts on a copy of the demo's process folder, each in the language's number format;
  <!-- index.speed added by TASK-WEB-011 (owner, 2026-11-08) -->
  IF a field holds another variable, THEN it SHALL report it and exit 1.
- **Rationale**: the only figure the site states in text is measured, never typed (measured on 2026-11-07: about one twelfth).
- **Priority**: Must
- **Acceptance Criteria**: Given the demo, When `build` runs, Then the index card states the two sizes and the ratio measured on it, with a
  decimal point in English and a comma in French; Given `{{unknown}}` in a field, Then the error names it.
- **Dependencies**: RQ-WEB-003

### RQ-WEB-006: French typography
- **Category**: Functional
- **EARS Type**: Ubiquitous
- **Statement**: The French page SHALL show a no-break space before `:`, a narrow no-break space before `;`, `?` and `!`, and typographic
  apostrophes, from a source written with ordinary spaces and straight apostrophes.
- **Rationale**: the owner types plain text; the page reads as proper French.
- **Priority**: Should
- **Acceptance Criteria**: Given `fr.md` with `construit ?` and `l'index`, When `build` runs, Then the page holds `construit ?` and
  `l’index`, And the English page is unchanged by the rule.
- **Dependencies**: RQ-WEB-003

### RQ-WEB-007: One page, two languages
- **Category**: Functional
- **EARS Type**: Event-driven
- **Statement**: The page SHALL hold the English text in its markup, complete before any script runs, and the French text as data; WHEN
  the reader chooses a language, the page SHALL show all its text in that language and remember the choice; the first visit SHALL follow
  the browser's language.
- **Rationale**: bilingual site (owner's choice of 2026-11-08), readable without script, one address to share.
- **Priority**: Must
- **Acceptance Criteria**: Given the page without script, Then it reads entirely in English; Given a browser in French, When the page
  opens, Then it reads in French; Given the switch, When English is chosen and the page is reopened, Then it reads in English.
- **Dependencies**: RQ-WEB-003

### RQ-WEB-008: The brand lockup in the header
- **Category**: Functional
- **EARS Type**: Ubiquitous
- **Statement**: The header SHALL show the AGNOS mark, beside it "AGNOS" in capital letters, bold and widely spaced, and below it the
  tagline "Agentic efficiency by traceability", smaller, of medium weight and in the muted text colour, as in the Performance Center's About topic.
- **Rationale**: the same lockup as the Performance Center, for continuity when the reader opens the demo (owner request of 2026-11-08).
- **Priority**: Must
- **Acceptance Criteria**: Given the page in a browser, When the header is read, Then "AGNOS" stands beside the mark and the tagline below
  it, aligned on the left, in each language and theme; And their colours, sizes and weights come from tokens.
- **Dependencies**: RQ-TRC-116, RQ-WEB-015

### RQ-WEB-009: The page's elements
- **Category**: Functional
- **EARS Type**: Ubiquitous
- **Statement**: The page SHALL hold, in this order: the hero (the thesis that agents write the code and the organisation keeps control,
  the link to the demo Performance Center, the three supported agent tools), the chain card (RQ-WEB-010), the tour of five Performance
  Center views (Matrix, Graph, History, Delivery, Quality, the order of the Performance Center; the Matrix in place of the Overview, amended by the owner on 2026-11-12, the order on 2026-11-13),
  each content section named after its view, two cards (the deterministic index, the design system), the close (the link
  to the demo, three steps to get started, each with an example command in a console style, amended by the owner on
  2026-11-13) and the footer (the developer documentation, the licence).
- **Rationale**: a decision maker's level: one question, one view, a few sentences each; the developer documentation is linked, never
  reproduced (owner review of 2026-11-08).
- **Priority**: Must
- **Acceptance Criteria**: Given the page, When it is read top to bottom, Then these elements appear in this order; And each tour stop
  shows its view's name, its question, what the reader sees, what makes it possible, its tags, its screenshot and its caption; And the
  History stop states that every commit, human, agentic or collaborative, can be traced (amended by the owner on 2026-11-12, the
  demo having agent identities since RQ-DMO-023).
- **Dependencies**: RQ-WEB-003

### RQ-WEB-010: The chain, human in the loop and on the loop
- **Category**: Functional
- **EARS Type**: Event-driven
- **Statement**: The chain card SHALL show requirement, decision and task as human in the loop, and tests then code, checklist and commit
  as human on the loop, each group with the Performance Center's human or agent icon and colour, ending on the Performance Center; WHEN
  the reader selects end-to-end supervision, the card SHALL show the whole chain human on the loop, the agent drafting and taking the
  decisions it was told it may take.
- **Rationale**: the owner's message: approval where it matters, supervision elsewhere, and full autonomy already possible by telling the
  agent so (owner, 2026-11-08).
- **Priority**: Must
- **Acceptance Criteria**: Given the card, Then the first three steps carry the human icon and the last ones the agent icon; When
  end-to-end supervision is selected, Then every step carries the agent icon and the approval reads as delegated; When the mixed mode is
  selected again, Then the first view returns.
- **Dependencies**: RQ-HST-026, RQ-WEB-015

### RQ-WEB-011: Each screenshot opens the demo
- **Category**: Functional
- **EARS Type**: Ubiquitous
- **Statement**: Each tour screenshot SHALL be a link to the address its field gives, under `demo/`, with a visible "open in the demo"
  label on hover and always on touch screens.
- **Rationale**: the screenshot is the real view; a click continues in the live demo (owner's option of 2026-11-08).
- **Priority**: Must
- **Acceptance Criteria**: Given the Graph screenshot written with `demo/PERF-CENTER.html#RQ-BKG-003`, When it is clicked, Then the demo

- **Dependencies**: RQ-WEB-002, RQ-TRC-016

### RQ-WEB-019: Screenshot ratio check
- **Category**: Functional
- **EARS Type**: Unwanted-behavior
- **Statement**: The page SHALL frame every image of `assets/screens/` at the ratio 16:9 of the owner's screen captures
  (1920 × 1080; 1291:720 until amended by the owner on 2026-11-13), given by a token of the site's design system; IF an image's ratio differs from it by more than 0.5% or its width is
  below 1920 px, THEN `build` SHALL fail naming the file, its size and the expected ratio.
- **Rationale**: a capture framed at another ratio is cropped; the owner reduces captures to any size of that ratio (owner request
  of 2026-11-12).
- **Priority**: Must
- **Acceptance Criteria**: Given the template, Then every screenshot and example frame takes its ratio from the token; Given images
  of 1920 × 1080 and 3840 × 2160, When `build` runs, Then it succeeds; Given an image of 1936 × 1080, 1600 × 1000 or 1280 × 720,
  When `build` runs, Then it fails naming that file and writes nothing.
- **Dependencies**: RQ-WEB-003, RQ-WEB-012, RQ-WEB-015

## Non-Functional Requirements

### RQ-WEB-013: Static files only
- **Category**: Non-Functional
- **NFR Type**: Portability
- **EARS Type**: Ubiquitous
- **Statement**: The site SHALL be static files that GitHub Pages serves as they are, with no server and no build step to view it, and no
  external resource other than its fonts and its links.
- **Metric**: number of external requests other than fonts at load: 0.
- **Measurement Method**: list the `src` and `href` of the built page.
- **Priority**: Must
- **Acceptance Criteria**: Given the built folder opened from disk, Then the page reads complete; Given its `src` and `href`, Then each is
  relative, a font from Google Fonts, or a link the reader follows.
- **Dependencies**: RQ-WEB-001

### RQ-WEB-014: Phone, themes, keyboard
- **Category**: Non-Functional
- **NFR Type**: Accessibility
- **EARS Type**: Ubiquitous
- **Statement**: The page SHALL read without horizontal scrolling from 360 px wide, in light and dark themes following the system, with
  every control reachable and operable by keyboard and text contrasts of at least 4.5:1.
- **Metric**: horizontal overflow at 360 px: 0 px; text contrast ≥ 4.5:1 in both themes.
- **Measurement Method**: the owner's visual check at 360 px and on desktop, in each theme; contrasts computed from the tokens.
- **Priority**: Must
- **Acceptance Criteria**: Given a 360 px window, Then no element overflows; Given each theme, Then every text token pair reaches 4.5:1;
  Given the keyboard only, Then the language switch, the chain switch and every link are reached and operated.
- **Dependencies**: RQ-WEB-015

### RQ-WEB-015: The site's design system
- **Category**: Non-Functional
- **NFR Type**: Maintainability
- **EARS Type**: Ubiquitous
- **Statement**: Every visual value of the page SHALL come from the design system, the Performance Center's tokens extended by the
  site's layer `assets/tokens.json`, so that the brand, identity and grade colours are the Performance Center's own; the template SHALL
  hold no raw visual value.
- **Metric**: raw colour, length or weight literals in the template's style outside token definitions: 0.
- **Measurement Method**: a test reads the template's style.
- **Priority**: Must
- **Acceptance Criteria**: Given the template, When its style is read, Then every visual value is a token variable; Given the human,
  agent and brand colours of the page, Then they are the Performance Center's tokens; Given a site token named as one of the
  Performance Center's, or referring to no token, When `build` runs, Then it fails naming it.
- **Dependencies**: ADR-WEB-001, ADR-TRC-002

### RQ-WEB-016: Maintainer only
- **Category**: Non-Functional
- **NFR Type**: Compliance
- **EARS Type**: Ubiquitous
- **Statement**: The skill SHALL be named with the `agnos-meta-` prefix, so that no release delivers it, and SHALL run Python's standard
  library only.
- **Metric**: files of the skill in a rehearsed release: 0.
- **Measurement Method**: `agnos-meta-release` rehearsal.
- **Priority**: Must
- **Acceptance Criteria**: Given a rehearsed release, Then it holds no file of `agnos-meta-website`; Given the script, Then it imports only
  the standard library.
- **Dependencies**: DEC-MTA-003
