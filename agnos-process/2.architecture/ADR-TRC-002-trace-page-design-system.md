# ADR-TRC-002: Design System of the Traceability Page
<!-- Amended on 2026-10-31: the skill, its script and its outputs carry their current names (RQ-TRC-104, RQ-TRC-105, DEC-TRC-055). -->

## Status
Accepted — required by AGNOS MANDATORY DESIGN SYSTEM before the first UI requirement of FTR-TRC-001. Motivated by
RQ-TRC-018; every UI requirement of FTR-TRC-001 (RQ-TRC-011 to RQ-TRC-016) and ADR-TRC-003 depend on it.

## Context
The page must look extremely professional: a consistent palette, typography, spacing and states, in a light and a dark
theme, readable by people with colour-vision deficiencies, and the graph drawn with the same colours as the tables. It is
generated by a script and styled by one CSS file and one script; without a single source of visual values, colours end up
duplicated between the CSS and the graph style. The process's design-system template
(`.github/skills/agnos-design-system/assets/design-system-template.md`) defines the three-tier token chain and its grep-checkable rules.

## Decision

### DEC-TRC-009: One token file in three tiers, compiled to CSS custom properties
`assets/tokens.json` holds the tokens: **global** (raw palette and scales: neutral and accent ramps, the six type hues,
type sizes, spacing steps, radii, strokes, durations), **semantic** (roles: surface, raised surface, text, muted text,
border, accent, focus ring, status ok/warn/error, one hue per element type and one for files and undefined IDs), each
with a `light` and a `dark` value that names a global token, and **component** (header, sidebar, card, table, chip,
badge, detail panel, graph node and edge), each naming a semantic token. The generator resolves the chain and writes
`:root{--…}` for light and `[data-theme=dark]` / `prefers-color-scheme: dark` for dark, in front of the page's CSS; it
fails (exit 1) when a reference does not resolve.

### DEC-TRC-010: No raw visual value outside the token file
`assets/matrix.css` uses `var(--…)` only; `assets/matrix.js` reads the graph colours, sizes and widths from the computed
custom properties (`getComputedStyle`) when it builds the Cytoscape style, and rebuilds it when the theme changes. A test
fails on any `#hex`, `rgb(`/`hsl(` or numeric `px`/`ms` literal in those two files (RQ-TRC-018). Unitless layout numbers
of the graph algorithm (iterations, padding ratios) are named constants at the top of the script.

### DEC-TRC-011: The visual language
- **Type**: the system UI font stack (`system-ui, Segoe UI, Roboto, Helvetica, Arial, sans-serif`), monospace stack for
  IDs, paths and code lines; no web font, the page is offline (RQ-TRC-010). Scale 12/13/14/16/20/28.
- **Colour**: a slate neutral ramp, one blue accent; the six element types use the Okabe-Ito colour-blind-safe palette,
  each also told apart by its node shape (round FTR, rounded rectangle RQ, hexagon ADR, diamond DEC, barrel PLAN,
  tag TASK, rectangle file, octagon undefined), so colour is never the only cue. Text on surfaces ≥ 4.5:1 (WCAG AA).
- **Space and shape**: 4-point spacing scale; radius 6 for controls and cards, 999 for chips; 1-point borders.
- **States**: hover, focus (a visible 2-point ring), selected and faded are tokens; the faded opacity of the graph is one
  token.

## Consequences
**Easier.** Restyling is a one-file edit; the graph and the tables cannot disagree on a type colour; the dark theme is free.
**Harder.** The script cannot use a literal colour for a quick fix; the token file has to be extended first.
**Constrained.** Graph styling goes through computed CSS values, read once per theme.

## Alternatives Considered
- **A CSS framework (Bootstrap, Tailwind).** Rejected: hundreds of kilobytes inlined into every page, and its own palette
  beside ours.
- **Tokens written directly as CSS custom properties.** Rejected: the three-tier rule and its resolution check need a
  structured source; JSON is read by the generator and the tests alike.
- **Hues chosen freely per type.** Rejected: not colour-blind safe.
